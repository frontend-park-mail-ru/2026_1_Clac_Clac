# Показ описания задачи при голосовании (оценивании)

## Текущее состояние

Шаблон `poll.hbs:74-76` УЖЕ содержит отображение описания:
```hbs
{{#if activeCardDescription}}
<p style="...">{{activeCardDescription}}</p>
{{/if}}
```

`KanbanPoll.ts:306` УЖЕ передаёт `activeCardDescription: cardDescription` в шаблон.

Код поиска описания в `KanbanPoll.ts:242-248`:
```ts
let cardDescription = "";
for (const section of state.sections) {
  const task = (section.tasks as any[]).find((t: any) => t.id === cardLink);
  if (task?.description) {
    cardDescription = task.description;
    break;
  }
}
```

**Проблема**: `task.description` в `kanbanStore.state.sections` может быть пустым/отсутствовать в двух случаях:

1. **Новая задача создана через плашку (inline)** — `KanbanActions.createTask:403-417` не включает `description` в объект `newTask`
2. **После редактирования задачи через панель** — `TaskActions.saveTask` сохраняет описание на сервер, но НЕ обновляет `kanbanStore` локально. Вместо этого вызывается `clearKanbanCache()` который сбрасывает `sections = []`.

## Решение

### Шаг 1: Добавить `description` в `newTask` при создании задачи

**Файл**: `src/modules/kanban/KanbanActions.ts:403-417`

Добавить `description: ""` в `newTask` (новая задача создаётся с пустым описанием):
```ts
const newTask: Task = {
    ...
    description: "",   // ← добавить
};
```

### Шаг 2: Обновлять описание в kanbanStore при сохранении из TaskView

**Файл**: `src/modules/task/TaskActions.ts:277-284`

После успешного `updateTask`, отправить action для обновления описания в kanbanStore:
```ts
appDispatcher.dispatch({
    type: "KANBAN_UPDATE_TASK_DESCRIPTION",
    payload: { taskId, description: payload.description },
});
```

**Файл**: `src/modules/kanban/KanbanStore.ts` — добавить обработчик:

```ts
case "KANBAN_UPDATE_TASK_DESCRIPTION": {
    const { taskId, description } = action.payload as { taskId: string; description: string };
    for (const section of this.state.sections) {
        const task = section.tasks.find((t) => t.id === taskId);
        if (task) {
            task.description = description;
            break;
        }
    }
    break;  // без emit("change") — без ререндера канбана
}
```

### Шаг 3 (опционально): При старте голосования — принудительная загрузка свежих данных

В `KanbanPoll.ts`, при открытии активного голосования, если `state.sections` пуст или устарел — вызвать `KanbanActions.fetchKanban(state.boardId!)`.

Но обычно этого не требуется, т.к. после старта голоса `fetchPoll` уже вызывает `fetchKanban`.

| # | Файл | Строки | Что |

| 1 | `KanbanActions.ts` | 403-417 | Добавить `description: ""` в `newTask` |
| 2 | `TaskActions.ts` | 278-284 | После `updateTask` → dispatch `KANBAN_UPDATE_TASK_DESCRIPTION` |
| 3 | `KanbanStore.ts` | ~280 | Добавить case `KANBAN_UPDATE_TASK_DESCRIPTION` |

## Результат

- При создании задачи описание = `""` (пустое, но поле существует)
- При открытии карточки → редактировании описания → сохранении → описание сразу попадает в `kanbanStore`
- При голосовании: `activeCardDescription` содержит актуальное описание
- Участники видят под названием задачи её описание
